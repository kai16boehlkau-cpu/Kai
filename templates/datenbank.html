🗄️ So sieht die Datenbank aus

Unser Kalorienzähler speichert alles in einer SQLite-Datenbank (database.db) direkt neben der Programmdatei. Es werden zwei Tabellen verwendet.

💾 SQLite · lokal
🔑 Primärschlüssel Spalte id – jede Zeile bekommt eine eindeutige Nummer. Damit kann Flask genau einen Eintrag ändern oder löschen.
📝 TEXT Textfeld – z. B. der Name „Apfel" oder das Datum „2026-10-22".
🔢 REAL Zahl mit Nachkommastellen – z. B. 379,5 kcal pro 100 g.
🔢 INTEGER Ganze Zahl – z. B. die berechneten Kalorien der Portion (227).

Tabellen-Diagramm

So ist database.db aufgebaut.

⚠️ Prüfungsrelevant
entries – alle Mahlzeiten-Einträge
  • id INTEGER PK
  • nameTEXT
  • calories_per_100gREAL
  • amount_gramsREAL
  • caloriesINTEGER
  • mealTEXT
  • dateTEXT
  • created_atTEXT

calories wird in Python berechnet: kcal_pro_100g × gramm / 100.

🔗 verknüpft Die Einstellungen liegen bewusst in einer eigenen Tabelle: So bleibt das Tagesziel (settings.daily_goal) getrennt von den Mahlzeiten (entries).
settings – Tagesziel & Status
  • id INTEGER PK
  • daily_goalINTEGER
  • goal_setINTEGER

goal_set: 0 = Ziel noch nicht festgelegt, 1 = vom Benutzer gespeichert. Es gibt immer nur eine Zeile (id = 1).

Zusammenfassung: Jeder Lebensmittel-Eintrag ist eine Zeile in entries. Das persönliche Tagesziel steht als einzelne Zeile in settings. Flask liest beide Tabellen mit parametrisierten SQL-Abfragen (Platzhalter ?), damit keine SQL-Injection möglich ist.
